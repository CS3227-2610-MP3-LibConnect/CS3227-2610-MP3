# Coding Agent Interaction Summary

Date: 2026-10-15

## Objective and context

Create a project-local set of Codex skills for specification-driven development and related coding-agent workflow tasks in `.agents/skills/`.

## Discussion summary

- Created `sdd-design` for gathering product requirements, inspecting source and project documents, proposing technical and integration specifications, and documenting the approved design under `specdocs/` only after approval. The user clarified source code may not yet exist; the skill should search for it and fall back to documents. The final design must also explain the current implementation gap and list new or modified capabilities.
- Created `sdd-propose` to turn a design into ordered checkbox tasks with descriptions and acceptance criteria. Follow-up updates require logical development order and, for approved deviations, updating the current design while preserving `## amendments` as a changelog; tasks must follow the updated design.
- Created `sdd-apply` to check that `design.md` and `tasks.md` agree before changing files, implement tasks sequentially, check off completed tasks, ask the user about unforeseen design decisions, and perform a final regression and specification review.
- Created `sdd-revise` to summarize current specification state and use separate approval gates for design changes and task-list changes. Approved changes are logged with reasons and dates in each document's amendments section.
- Created `sdd-archive` to verify task completion, inform the user about incomplete or unverifiable tasks, and require informed approval before moving a specification folder to `sdddocs/completed/`.
- Created `summarise-chat` to produce factual coding-agent interaction logs. Added a directory parameter: `$summarise-chat junhong` saves under `docs/logs/junhong/` using the next numeric Markdown filename.
- Created `yeet` to handle `staged` or `all` changes, propose an exact commit message, and require explicit approval before committing. Updated it to always stage `docs/logs/` changes in either mode.

## Key decisions and rationale

- Keep the skills in the project's `.agents/skills/` directory so they are available in this repository.
- For specification planning, source code is useful context when present, but its absence is not a blocker; use project documentation instead.
- Require user clarification or approval where behavior or scope is uncertain, and preserve approval boundaries for document edits, implementation, archiving, and commits.
- Keep amendment history in specification documents so approved deviations and revisions remain traceable.
- Number saved chat logs by incrementing the largest numbered `.md` filename in the selected log directory.
