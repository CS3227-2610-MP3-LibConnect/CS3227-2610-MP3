## Key decisions and rationale
- Keep assistant guidance read-only; the model cannot select identity, access member records, or change app state.
- Keep personal data assembly and ownership scoping on the authenticated server. Compute capacity from `ACTIVE` loans using `max(0, 10 - activeLoanCount)`.
- Use process-local rate counters because production is expected to have one server instance; no Firestore global counter is required.
- Return a stable, safe API error when personalized member data is unavailable, per the user’s selection.
- Do not commit until the user approves the exact proposed message, as required by the `yeet` workflow.
