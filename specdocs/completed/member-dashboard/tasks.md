## Repository conventions and dependencies

- React Router routes are in `apps/client/src/App.tsx`; `BrowserRouter` is provided in `apps/client/src/main.tsx`.
- `ProtectedRoute` uses restored session state from `AuthContext` and enforces the requested account type. Keep server-side active-actor checks authoritative (`apps/client/src/auth/ProtectedRoute.tsx`, `apps/client/src/auth/AuthContext.tsx`, `apps/api/src/http/auth.ts`).
- Client API requests use `apiRequest`, which includes cookies, and catalog list requests return `{ items, page: { limit, nextCursor } }` (`apps/client/src/api/base.ts`, `apps/client/src/api/catalog.ts`, `apps/api/src/routes/catalog.ts`).
- Catalog query validation is strict and uses Zod. Repository search combines exact filters with case-insensitive substring matching, AND semantics, and cursors bound to filters (`apps/api/src/routes/catalog.ts`, `apps/api/src/storage/repositories.ts`).
- Book detail returns `{ book, copies, availability }`; book records contain no image field, and book cards omit cover images and placeholders (`apps/api/src/routes/catalog.ts`, `packages/shared/src/domain/records.ts`).
- The existing verification convention is Node’s built-in test runner with `npm test`; Firestore-backed API verification uses the configured emulator (`package.json`, `tests/client-auth.test.mjs`, `tests/verify-auth-emulator.mjs`, `firebase.json`).
